New concrete result
The previously unidentified main RLCG body contains a coherent candidate for
SMU5/6 -> LX6 command32. This is substantially stronger than matching scratch
layouts alone, but depends on a partial inferred RLCG instruction reading.
No complete ISA specification or observed execution is available here.

Xtensa counterpart and timing consequence
83fc uses base6803b600, command+64, parameter+68 (hex), exactly matching the
candidate sender's DWORDed99/ed9a after multiplying by4. Initial commandtable
entry32 is5fff8537. That branch normalizes parameter1 to a boolean, then calls
1d10 at8545. 1d10 reads35scratchwords only on its nonzero-argument path;
zero takes1f54. Thus the candidate bridge assigns the import to later SMU5,
not the immediate post-transfer SMU6. It agrees with SMU2af68 mapping1->5,
other->6 and the conditional6-then5 sequence already recorded.

Limits and next work
